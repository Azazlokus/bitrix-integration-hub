# 0002. Раскладка Docker-окружения и версии сервисов

- **Статус:** Accepted
- **Дата:** 2026-11-01
- **Этап ТЗ:** 1

## Контекст

ТЗ требует: свой код только в `local/`, ядро (`bitrix/`, `upload/`) не в git, PHP 8.2+, MySQL 8, docker-compose со всеми сервисами. Нужно решить, где DOCUMENT_ROOT и какие версии брать (проверено 2026-11-01 по Docker Hub и endoflife.date).

## Рассмотренные варианты

### DOCUMENT_ROOT

1. **Корень репозитория = вебрут.** Просто, но наружу смотрят `docker/`, `docs/`, `tests/`, `.env`, `Makefile` — нужно запрещать каждый путь в nginx, легко забыть.
2. **`www/` = вебрут, `local/` монтируется внутрь (`./local → /app/www/local`).** В вебруте только то, что положено Битриксу; `local/` остаётся в корне репо, как в ТЗ. Минус: вложенный bind-mount, в `www/` появляется пустая точка монтирования `local/`.
3. **Симлинк `www/local → ../local`.** Ломается на Windows-хостах и в части инструментов Битрикса.

### Версии

| Сервис | Взяли | Альтернатива | Почему |
|---|---|---|---|
| PHP | 8.4.27 (trixie) | 8.3 | решение пользователя; поддержка до 2028. Официальной таблицы совместимости БУС с 8.4 не найдено — проверяем `site_checker` после установки. Откат на 8.3 — **не одна переменная**: `PHP_VERSION` в `.env`, `platform.php` и PHPUnit 13→12 в `local/composer.json`, `@PHP8x4Migration` → `@PHP8x3Migration` и скобки вокруг `new X()` (синтаксис 8.4) — `make fix` |
| MySQL | 8.4 LTS | 8.0, 9.7 LTS | 8.0 — EOL 04.2026; 9.x Битрикс официально не заявляет |
| Redis | 8.10 | Valkey 9.1 (BSD) | ТЗ называет Redis; для локальной учебной среды лицензия (AGPL/RSAL) не важна, Valkey совместим по протоколу — замена одной строкой |
| RabbitMQ | 4.4-management | 4.3 | 4.3 — EOL 01.2027 |
| nginx | 1.30 stable | 1.31 mainline | stable-ветка |
| Стиль кода | PER-CS 3.0 | PSR-12 | PER-CS — официальный преемник PSR-12 от PHP-FIG, включает его правила |

## Решение

Вариант 2 для вебрута. PHP-контейнер видит весь репозиторий как `/app` (composer, тесты, `tools/`), nginx — только `www/` и `local/` (read-only), служебные каталоги `local/` (`modules`, `vendor`, `logs`, `php_interface`, `routes`) закрыты в nginx.
PHP-FPM работает от UID/GID пользователя хоста — файлы, которые создаёт мастер установки, не принадлежат root.
Все порты публикуются только на `127.0.0.1`; Redis наружу не публикуется.

## Последствия

- Публичные страницы сайта (этап 3) коммитятся в `www/` явными исключениями в `.gitignore`.
- Composer `autoload-dev` (`../tests`, `../tools/src`) корректно работает только из CLI (`/app/local`), в веб-контексте эти классы не нужны.
- При смене версии PHP нужна пересборка образа (`make build`).
- Кеш и сессии — в одном Redis с `allkeys-lru` без персистентности: после рестарта или под давлением памяти сессии теряются. Для лабы приемлемо; для прода — отдельный инстанс/БД для сессий и `volatile-lru`.
- FastCGI php-fpm доступен только сетям `app` (nginx, worker, mock-services); туннель видит лишь nginx `:8081` с allowlist путей.
