# 0001. Conventional Commits без Node.js и DevSecOps-пайплайн на GitHub Actions

- **Статус:** Accepted
- **Дата:** 2026-10-31
- **Этап ТЗ:** 0 (подготовка), 17

## Контекст

Нужны Conventional Commits (история → CHANGELOG и semver) и проверки безопасности до появления кода. Проект PHP-шный; Node.js понадобится только на этапе 15 (Laravel), и то не обязательно.

## Рассмотренные варианты

1. **commitlint + husky** (Node) — стандарт де-факто, но тянет `node_modules` в корень PHP-проекта ради одного хука.
2. **lefthook** (Go-бинарь, v2.2.2) — быстрый, удобный конфиг, но ещё одна утилита, которую нужно ставить каждому.
3. **Свой shell-скрипт** `tools/check-commit-msg.sh` + `core.hooksPath=.githooks` — ноль зависимостей; один и тот же скрипт работает в git-хуке и в CI, scope'ы привязаны к этапам ТЗ.

Безопасность: CodeQL не поддерживает PHP, поэтому SAST — Semgrep; зависимости/IaC — Trivy (один инструмент вместо отдельных hadolint/composer-scanner на старте), секреты — gitleaks.

## Решение

Вариант 3. Если понадобятся сложные правила (footer, ссылки на issue) — перейти на lefthook + commitlint.
Все GitHub Actions закрепляются по SHA (актуальные версии проверены 2026-10-31), права — минимальные на уровне job.

## Последствия

- Нет внешних зависимостей для разработчика; `make hooks` — единственный шаг.
- Список scope'ов нужно поддерживать в скрипте вручную при появлении новых областей.
- Загрузка SARIF требует публичного репозитория или GHAS.
