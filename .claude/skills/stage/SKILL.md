# Этап $ARGUMENTS

1. **Контекст.** Прочитай этап $ARGUMENTS в `docs/roadmap.md`, соответствующий раздел исходного ТЗ (колонка «Основа в ТЗ»), раздел 0 ТЗ (правила) и `docs/progress.md`. Убедись, что предыдущие этапы закрыты; если нет — скажи пользователю.
2. **Ревизия актуальности.** Для каждой новой зависимости/образа/сервиса из этапа проверь текущую стабильную версию и нет ли лучшей альтернативы. Если ТЗ предлагает устаревшее — предложи замену с аргументами.
3. **План.** Список файлов, портов/адаптеров, таблиц/миграций, тестов, и как будет проверена каждая строка «Приёмки». Развилки — вопросом пользователю; решения — ADR (`/adr`). Дождись согласия, если план меняет архитектуру.
4. **Ветка.** `git switch -c feat/stage-<N>-<short>` (если работаем через PR).
5. **Реализация** маленькими шагами; после каждого логического шага — тесты + conventional-коммит со scope этапа.
6. **Ручные шаги**, которые может сделать только человек (установка БУС, портал Б24, токены) — опиши в README/доке интеграции пошагово, не имитируй их выполнение.
7. **Приёмка.** Пройди каждый пункт «Приёмки» и покажи доказательство (вывод команды, тест, лог). Что не удалось проверить — честно перечисли.
8. **Ревью.** Запусти агента `bitrix-reviewer` по диффу этапа; при работе с вебхуками/авторизацией/секретами — ещё `security-reviewer`. Исправь найденное.
9. **Документация.** Обнови `docs/progress.md` (статус, что сделано, отклонения, долги), `docs/architecture.md`, `docs/integrations/<код>.md` по шаблону (включая раздел «В Laravel это было бы…»), `make demo-<код>`, `.env.example`.
10. **Финальный коммит** `docs(<scope>): update progress for stage <N>`. Не пушь без просьбы.
